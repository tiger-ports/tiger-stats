# Test-first observations

Local macOS 15.8.2 x86_64; commands run from project root. Tests and their API declarations were written before their implementations.

1. CPU delta: compiling `tests/test_monitor.c` before `st_cpu_percent` existed failed at link time with undefined `_st_cpu_percent`. After implementing the calculation, the test printed `PASS cpu delta`.
2. Counter rollover and zero/null handling: the initial modular implementation passed the rollover case but failed with `FAIL zero delta must return error and preserve output`. After guarding zero and null, the suite printed `PASS cpu delta`, `PASS cpu rollover`, `PASS cpu zero delta`, and `PASS cpu null arguments`.
3. Formatting and error handling: adding format tests failed to link due to missing `_st_format_cpu` and `_st_format_memory`; implementing them produced `PASS formatting` and `PASS formatting errors` alongside earlier passing tests.
4. Live Mach readers: adding live sample and null-input tests failed to link due to missing `_st_read_cpu` and `_st_read_memory`; after implementation the test printed `PASS live Mach CPU and memory`.
5. Headless application integration: `sh tests/test_cli.sh` before the application existed failed with `FAIL: app executable missing`. After implementing and packaging the app, `make test` passed the CLI self-check and option-error test.
6. Menu tracking: the new timer-mode test initially failed to link because `st_schedule_update_timer` did not exist. After adding registration for both default and event-tracking run-loop modes, the test passed in both modes. This tests the run-loop behavior, not an actual open menu.
7. Physical-memory error: a test simulating failed `hw.memsize` and a misleading 32-bit `hw.physmem` initially failed because the fallback was accepted. After removing the fallback, it passed by reporting memory unavailable.
8. Root disk self-check: the new CLI assertion initially printed `FAIL: root disk capacity missing from self-check` (exit 1). After wiring the reader/formatter into self-check, it passed.
9. Disk capacity conversion/format: first compilation of the new deterministic test failed to link due to missing `_st_disk_from_blocks` and `_st_format_disk`; after implementing them it printed `PASS disk available capacity and formatting`.
10. Invalid capacity: the next test printed `FAIL disk invalid/overflow values or modified output`; after validating block counts and checking multiplication overflow it passed, including zero available blocks.
11. Format errors: the next test printed `FAIL disk format accepts zero total`; after input validation, null, inconsistent and small-buffer cases passed without changing the output.
12. Root reader: compiling the simulated `statfs` test failed to link due to missing `_st_read_disk`; after implementation the test passed, including root path, non-superuser available rather than free blocks, failed `statfs`, and malformed samples. Additional negative, inconsistent and overflowing samples were added afterward. The tests use a replacement `statfs` for deterministic failure paths; the CLI self-check exercises the real call.

13. Network delta: `tests/test_network.c` initially failed to link without `st_network_update`; after adding the baseline/delta calculation, it passed.
14. Counter decrease: the next test failed at `st_network_update(&state, &a, &rate) != 0`; after rejecting decreasing counters and replacing the baseline, it passed.
15. Interface churn and reorder: the next test failed on a renamed/reindexed interface; after matching by name and index and rejecting changed sets, it passed, including reordering and adding/removing interfaces.
16. Time and failures: the next test failed on an overlong interval; after validating time and interval and clearing the baseline for failed/empty samples, it passed zero intervals, overlong intervals, NaN, no entries and simulated read errors.
17. Reader: the injected `getifaddrs`/clock test initially failed to link without `st_read_network`; after implementation it passed active/link filtering, loopback and inactive exclusion, counters, read/clock errors, missing data and no entries. Additional malformed/duplicate and null-argument cases were added afterward. The reader test includes the real implementation with only OS calls substituted.
18. Formatting: the next test failed to link without `st_format_network`; after implementation it passed value, NaN and short-buffer checks.
19. CLI integration: `sh tests/test_cli.sh` initially reported `FAIL: network throughput missing from self-check`; after wiring the reader/formatter into self-check and the build, it passed.
20. Extreme interval: a finite-sample overflow test failed because an infinite rate was accepted; after validating the result, it passed without modifying output. Additional outbound-decrease, backward-clock, boundary-interval, duplicate and infinity cases were added afterward.

The full suite was rebuilt and passed locally with `-Werror` (deprecation warnings explicitly disabled), and the standalone headless self-check passed. Link failures are recorded as missing-implementation evidence, not as runtime assertion failures. GUI functionality has only been compiled, not launched or tested. Tests do not simulate Mach API failures or validate the hardware-dependent total-memory reading on Tiger; neither disk behavior nor this new source has been tested on Tiger.

## Disk explorer

* The scan engine and `tests/test_space_scan.c` predate this explorer integration. Its fixture test covers sorted logical sizes, hard links, symlinks, inaccessible and replaced directories, volume boundaries, node/depth caps, and overflow.
* Chart geometry test was written first: strict compilation/linking failed with undefined `st_space_chart_slice`. After implementation it printed `PASS disk chart proportions, zero and overflow`.
* Navigation test was written first: linking failed with undefined `st_space_nav_init`, `st_space_nav_current`, `st_space_nav_enter` and `st_space_nav_up`. After implementation it printed `PASS disk navigation stays inside scanned tree`.
* The Objective-C worker/controller was then implemented; a subsequent headless test (not a test-first red/green cycle) checks an actual background scan, main-thread completion, closed-window discard, and controller deallocation. It printed `PASS background scan delivers on main thread and discards closed result`. It does not create a window or validate drawing or interaction.
* `TMPDIR="$HOME/.hermes/cache/scratch" make -B test CFLAGS='-O2 -Wall -Wextra -Werror -Wno-deprecated-declarations -std=gnu99'` rebuilt and passed the full local suite and headless CLI integration. No GUI was launched, and no Tiger/PowerPC build or runtime test was performed. TDD was applied to the chart and navigation helpers, not every Objective-C method.
* The scan fixture also passed a local `-fsanitize=address,undefined` build; chart and navigation tests separately passed with `-pedantic -Werror`.
* Review regression: an injected inaccessible scan root initially returned a successful zero-byte partial tree. The new test failed with `FAIL inaccessible root must return EACCES and no tree`; the implementation now returns the underlying error and no tree. Additional tests cover a failed root recheck and an opened directory whose identity differs. Inaccessible descendants remain visibly partial. The full suite and the address/undefined sanitizer scanner test passed after the fix.
* The worker-lifetime test now releases its external controller reference immediately after dispatch and asserts main-thread completion and eventual deallocation. It passes locally; no actual window or Tiger runtime has been exercised.
* A synthetic 60/30/10 chart fixture was rendered offscreen to a PNG and visually inspected on macOS 15: the colored donut appeared in proportion. This does not exercise the full window, table interaction, or Tiger display.

## Explorer refresh

* The first headless controller test was written before refresh implementation; it compiled but failed with unrecognized selector `selectPath:`. After implementation it passed deterministic manual/timer requests, overlap prevention, failure retention, modal suppression, navigation reset, close, reopen and stale-result handling. Subsequent assertions cover partial-result/error text, real timer cadence and default/tracking run-loop delivery; they were added after implementation.
* A later headless integration test uses a real background worker and main-thread delivery, changes a temporary fixture file from 3 to 8 bytes, and verifies manual refresh updates the result. The pre-existing worker test checks closed-result discard and controller lifetime. These do not exercise actual window rendering, user interaction, or Tiger.
* A full forced local `make test` with `-Werror` passed; deprecation warnings were disabled. No GUI was activated and no Tiger/PowerPC build or runtime was performed.
* Timer ownership regression was written first: releasing the sole external owner with an open, real scheduled timer and a completed scan failed the deallocation/invalidation assertion. A main-thread-confined non-retaining timer target now breaks the cycle, temporarily retains the explorer during a tick, and is cleared before invalidation. The test passes after draining its inner autorelease pool; both run-loop timer modes remain covered.
* Retry status regression was written first: after a failed refresh, the next in-flight retry failed the assertion that the old error remains visible with the old tree. Keeping the error until an accepted result arrives makes the test pass, including clearing it on a successful (partial) result.
* Additional real-worker coverage releases the external owner with a live timer and scan; it checks main-thread delivery, continued worker ownership, eventual deallocation and timer invalidation. An additional synchronized regression paused the original controller-targeted thread after posting its result: main-thread delivery before thread exit led to controller deallocation on the worker thread. The scan now runs in a separate thread-retained job, while the controller's explicit retain lasts through main-thread delivery; a paused-job test verifies deallocation and timer invalidation on the main thread before the job exits. The synchronized test passed 50 local repetitions. Closing remains non-cancellable: existing tests cover discarding a closed or stale result. The full forced strict local suite, including fake-Workspace Trash tests, passed; GUI and Tiger remain untested.

## Single-file Trash

* The first identity-validation fixture was written before implementation; strict linking failed with undefined `st_space_trash_validate`. After implementation it passed. Later fixtures cover hard links, symlinks, directories, missing and foreign identities, traversal, changed/deleted/replaced leaves, changed parents and changed root identity. Fixtures are the only files removed; tests never move anything to Trash.
* The first headless controller test was written before the action and failed with unrecognized selector `moveToTrash:`. It then passed using a fake workspace. Subsequent coverage verifies the exact native operation/source/destination/single-file payload, cancel, busy scan, refresh during confirmation/workspace call, replacement during confirmation, success, failure, negative and positive tags, inconsistent failure-plus-positive tag, and close while pending. These later cases were added after initial implementation. The strict byte-representation test was added before exposing its helper; it initially failed to link without `STSpaceExactPath`, then passed, including invalid UTF-8 and Unicode round-trip behavior.
* Headless mocks do not verify a real Workspace operation, actual modal rendering, or behavior on Tiger. Path revalidation does not eliminate the race between checking a name and the Workspace operation. No user file was moved or deleted.
* A later fake-Workspace integration case runs the real scan worker and main-thread callback and verifies that the refreshed tree is passed to a fake chart. A forced full local `make test` passed with `-Werror` (deprecation warnings disabled); scanner, Trash identity and headless controller tests also passed under address/undefined sanitizers. These tests do not activate the GUI or establish Tiger compatibility.
* Pending-result refresh regression was written before the fix and failed because a positive tag started no read-only scan. The fake-Workspace/synthetic-worker test then passed for pending and contradictory tags, manual and timer refresh, non-overlap, mutation/confirmation lock, warning during scans and after success/error, and close/reopen with stale completion discarded before a queued scan. Additional post-fix checks exercise an actual scheduled timer, disappearance of the fixture without unlocking, and a real background worker observing a synthetic file grow while pending. A forced full local `-Werror` suite and address/undefined sanitizer runs for scanner, Trash, refresh, lifecycle and UI tests passed. No real Trash operation or GUI was exercised.
* The historical [Leopard reference](https://leopard-adc.pepas.com/documentation/Cocoa/Reference/ApplicationKit/Classes/NSWorkspace_Class/Reference/Reference.html) specifies an empty destination string, whereas the modern installed SDK header specifies `nil`. A fake-Workspace regression expecting `nil` failed against the original unconditional empty string; the code now selects the documented form for the SDK in use, and the full local suite passes. The Tiger branch and both real Workspace behaviors remain untested.
